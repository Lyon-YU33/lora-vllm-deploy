## 📚 前置知识学习

开始实践前，建议先阅读以下资料（不必完全看懂，带着问题边做边学）：

### LoRA 微调原理
- 📄 **原始论文**：[LoRA: Low-Rank Adaptation of Large Language Models](https://arxiv.org/abs/2106.09685)
- 🎯 **中文图解**：[深入理解 LoRA：低秩适配器原理详解](https://zhuanlan.zhihu.com/p/623543377)
- 💡 **核心思想**：用两个小矩阵 A 和 B 的乘积近似权重更新 ΔW = BA，将可训练参数从亿级降到百万级。

### vLLM 推理引擎原理
- 📄 **官方论文**：[Efficient Memory Management for Large Language Model Serving with PagedAttention](https://arxiv.org/abs/2309.06180)
- 📖 **官方文档**：[vLLM Documentation](https://docs.vllm.ai/)
- 💡 **核心思想**：借鉴操作系统的虚拟内存分页机制，管理 KV Cache，将显存碎片化问题解决，吞吐量提升 2-4 倍。

### DeepSpeed 分布式训练
- 📄 **ZeRO 论文**：[ZeRO: Memory Optimizations Toward Training Trillion Parameter Models](https://arxiv.org/abs/1910.02054)
- 💡 **核心思想**：将优化器状态、梯度、参数分片到多卡，降低单卡显存压力。

### GPTQ 量化原理
- 📄 **原始论文**：[GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers](https://arxiv.org/abs/2210.17323)
- 📖 **中文解读**：[GPTQ 量化算法详解](https://zhuanlan.zhihu.com/p/627286834)
- 💡 **核心思想**：基于二阶信息的逐层量化算法，在 4-bit 量化下保持接近 FP16 的精度。

## ⭐ 阶段 4：LoRA 微调训练（核心步骤）

### 4.1 理解 YAML 配置文件

打开 `configs/qwen25_lora.yaml`，重点理解：

```yaml
# === LoRA 核心超参（你最该理解的）===
lora_rank: 8           # LoRA 秩 r，决定 ΔW 的"信息容量"
                       #   r=4: 极简，参数少但效果可能差
                       #   r=8: 平衡（推荐）
                       #   r=64: 接近全量微调，但失去 LoRA 优势

lora_alpha: 32         # 缩放系数 α，最终 ΔW = α/r * BA
                       # 经验值: alpha = 4 * rank

lora_target:           # 选择对哪些层应用 LoRA
  - q_proj             #   矩阵分解的"低成本"选择
  - k_proj
  - v_proj             #   v_proj 最关键，论文证明它最重要
  - o_proj
  - gate_proj
  - up_proj
  - down_proj
```

> **论文对应**：LoRA 论文 Section 4.2 探讨了不同 target_modules 的效果对比。

## ⭐ 阶段 6：GPTQ 量化

### 6.1 理解量化原理

量化前先理解：
- **FP16**: 每个参数用 16 位（2 字节）表示，7B 模型 = 14GB
- **INT4**: 每个参数用 4 位（0.5 字节）表示，7B 模型 = 4GB
- **GPTQ**: 一种"事后量化"算法，通过校准数据集最小化量化误差

> **GPTQ 论文**：[arxiv.org/abs/2210.17323](https://arxiv.org/abs/2210.17323)

### 6.2 执行量化

```bash
# 切换到 deploy_env
conda deactivate
conda activate deploy_env

# 开始量化（约 1-2 小时）
python scripts/05_quantize_gptq.py \
    --model merged_model/qwen25-7b-lora-merged \
    --output quantized_model/qwen25-7b-gptq \
    --bits 4 \
    --group-size 128 \
    --calibration-samples 10
# 注: 示例数据只有 10 条，所以 calibration-samples 也设 10
# 实际项目中建议用 128 条以上
```

### 6.3 观察量化过程

终端会输出：

### 6.4 领悟量化机制

思考：
1. **量化为什么能省显存？**
   - 4 位 vs 16 位，参数存储减少 4 倍
   - 推理时直接用 INT4 矩阵乘法，速度也快

2. **量化为什么需要校准数据？**
   - 直接均匀切分会损失精度
   - GPTQ 用校准数据集的 Hessian 矩阵，逐列调整量化误差

3. **量化对效果影响多大？**
   - 论文证明困惑度（PPL）增加 < 1
   - 实际任务（摘要/翻译）影响通常 < 2%

> **量化算法对比**：[GPTQ vs AWQ vs BNB](https://github.com/IST-DASLab/gptq/blob/main/README.md)

## ⭐ 阶段 7：vLLM 部署

### 7.1 理解 vLLM 的核心优势

启动前先理解 vLLM 为什么快：

1. **PagedAttention**：把 KV Cache 像操作系统管理虚拟内存一样分页管理
   - 传统推理：每个请求预分配最大长度显存 → 大量浪费
   - PagedAttention：按需分配，显存利用率从 20% → 90%

2. **连续批处理**：动态组装多个请求的 batch
   - 传统推理：等一批全部完成才开始下一批
   - vLLM：哪个请求先生成完就先结束，新请求立即插入

> **vLLM 论文**：[arxiv.org/abs/2309.06180](https://arxiv.org/abs/2309.06180)
> **官方文档**：[docs.vllm.ai](https://docs.vllm.ai/)

### 7.2 启动 vLLM 服务
