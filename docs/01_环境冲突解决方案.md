# 环境冲突解决方案

> 本文档详细说明本项目如何解决原项目的环境冲突问题，并提供从零开始的配置步骤。

## 📌 总览：从 3 个环境到 2 个环境

### 原项目的 3 个环境

```
[llm_env: torch 2.5.1]
   ├─ LLaMA-Factory
   ├─ DeepSpeed
   └─ peft
        ↓ (训练产出 adapter，需手动搬运)
[gptq_env: torch 2.8.0]
   └─ gptqmodel  ← 与 llama-factory 冲突！
        ↓ (量化产出 GPTQ 模型，需手动搬运)
[部署环境: torch 2.8.0]   ← 其实和 gptq_env 重复
   └─ vllm
```

### 本项目的 2 个环境

```
[train_env: torch 2.5.1]   ← 训练 + 合并
   ├─ LLaMA-Factory
   ├─ DeepSpeed
   └─ peft
        ↓ (脚本自动传递路径)
[deploy_env: 与 CUDA 驱动匹配的 vLLM 环境]  ← 量化 + 部署
   ├─ AutoGPTQ   ← 替代 gptqmodel，更稳定
   └─ vllm
```

## 🔧 详细配置步骤（从零开始）

### 第 1 步：安装 conda

如果还没装 conda，先安装 Miniconda：

```bash
# 在 AutoDL 实例上通常已预装，跳过此步
# 本地安装参考: https://docs.conda.io/en/latest/miniconda.html
```

### 第 2 步：创建训练环境（train_env）

```bash
# 1. 创建环境
conda create -n train_env python=3.11 -y

# 2. 激活环境
conda activate train_env

# 3. 安装 PyTorch 2.5.1 (CUDA 12.4)
pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu124

# 4. 安装训练依赖
pip install -r requirements/requirements-train.txt

# 5. 验证安装
python -c "import torch; print(f'PyTorch: {torch.__version__}, CUDA: {torch.cuda.is_available()}')"
# 期望输出: PyTorch: 2.5.1+cu124, CUDA: True
```

### 第 3 步：创建部署环境（deploy_env）

```bash
# 1. 退出训练环境
conda deactivate

# 2. 创建部署环境
conda create -n deploy_env python=3.11 -y

# 3. 激活环境
conda activate deploy_env

# 4. 先按 vLLM 官方 GPU 安装指南安装与 CUDA 驱动匹配的 vLLM 二进制
# https://docs.vllm.ai/en/v0.11.0/getting_started/installation/gpu.html

# 5. 安装项目补充依赖（不手工固定 PyTorch/CUDA wheel）
pip install -r requirements/requirements-deploy.txt

# 6. 验证 vLLM 安装
python -c "import vllm; print(f'vLLM: {vllm.__version__}')"
# 期望输出: vLLM: 0.11.0
```

## 🎯 为什么要用 AutoGPTQ 替代 gptqmodel？

### 冲突根源

```
gptqmodel
    └─ 要求 torch >= 2.8.0

llama-factory
    └─ 锁定 torch == 2.5.1
```

两者无法共存于同一 conda 环境，原项目因此被迫拆出独立的 gptq_env。

### AutoGPTQ 的优势

| 对比项 | gptqmodel | AutoGPTQ |
|--------|-----------|----------|
| 维护状态 | 较新但更新频繁 | 成熟稳定 |
| torch 版本要求 | ≥ 2.8.0 | 兼容范围广 |
| 文档完整度 | 一般 | 优秀 |
| 社区支持 | 较小 | 庞大 |
| 在 deploy_env 中运行 | ✓ | ✓ |

**关键决策**：本项目用 AutoGPTQ 在 deploy_env 中独立完成量化，与 train_env 完全解耦。

### 环境切换说明

只有 **第 3 步 → 第 4 步** 之间需要切换环境：

```bash
# 完成 train_env 的工作后
conda deactivate

# 切换到 deploy_env 继续
conda activate deploy_env
```

其他步骤都在各自环境内连续执行。

## 🛡️ 常见问题排查

### Q1: `ImportError: cannot import name '...' from 'torch'`

**原因**：在错误的环境中运行了脚本

**解决**：
```bash
# 训练相关脚本必须在 train_env 运行
conda activate train_env

# 量化/部署相关脚本必须在 deploy_env 运行
conda activate deploy_env
```

### Q2: vLLM 启动时报 `torch version mismatch`

**原因**：deploy_env 中的 torch 版本不对

**解决**：
```bash
conda activate deploy_env
python -c "import torch; print(torch.__version__)"
# 必须是 2.8.0，如果不对就重装:
# pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu126
```

### Q3: LLaMA-Factory 训练时报 `deepspeed init error`

**原因**：未正确配置 DeepSpeed 或 CUDA 不可见

**解决**：
```bash
conda activate train_env
# 检查 GPU 可见性
nvidia-smi
# 检查 DeepSpeed
ds_report
```

### Q4: AutoGPTQ 量化速度很慢

**原因**：校准样本太多或 max_seq_length 太长

**解决**：调整 `05_quantize_gptq.py` 的参数
```bash
python scripts/05_quantize_gptq.py --calibration-samples 64 --max-seq-length 512
```
