## 🛠️ 微调框架对比

### 本项目使用：LLaMA-Factory
- **优点**：中文社区支持最好、配置简单、支持 100+ 模型
- **缺点**：对 torch 版本要求严格

### 其他可选框架

#### 1. Axolotl
- **特点**：YAML 配置驱动，支持多种数据格式
- **GitHub**：https://github.com/axolotl-ai-cloud/axolotl
- **适用场景**：需要处理复杂多模态数据集时
- **不选原因**：配置项较多，对初学者不友好

#### 2. Unsloth
- **特点**：极致速度优化，比标准训练快 2-5 倍
- **GitHub**：https://github.com/unslothai/unsloth
- **适用场景**：追求训练速度、单卡训练
- **不选原因**：对模型支持有限（主要支持 LLaMA/Mistral 系列），文档以英文为主

#### 3. PEFT 原生（HuggingFace）
- **特点**：最底层的 LoRA 训练接口
- **GitHub**：https://github.com/huggingface/peft
- **适用场景**：需要完全自定义训练流程
- **不选原因**：需要自己写训练循环，代码量大

#### 4. TRL 原生（HuggingFace）
- **特点**：强化学习训练（RLHF/DPO/PPO）官方实现
- **GitHub**：https://github.com/huggingface/trl
- **适用场景**：需要 RLHF 或 DPO 对齐
- **不选原因**：本项目只做 SFT 监督微调，不需要 RL

#### 5. FastChat
- **特点**：老牌框架，主要面向聊天机器人
- **GitHub**：https://github.com/lm-sys/FastChat
- **适用场景**：构建多 agent 对话系统
- **不选原因**：维护较少，新模型支持慢

## 🛠️ 量化框架对比

### 本项目使用：AutoGPTQ
- **优点**：稳定、文档完善、与 vLLM 兼容性好
- **缺点**：量化速度比新一代框架稍慢

### 其他可选框架

#### 1. GPTQModel
- **特点**：AutoGPTQ 的继任者，速度更快
- **GitHub**：https://github.com/ModelCloud/GPTQModel
- **适用场景**：追求最快量化速度
- **不选原因**：依赖 torch ≥ 2.8.0，与训练环境冲突（这是本项目要解决的核心问题）

#### 2. BitsAndBytes (NF4 4-bit)
- **特点**：HuggingFace 官方推荐，QLoRA 微调用
- **GitHub**：https://github.com/bitsandbytes-foundation/bitsandbytes
- **适用场景**：训练时直接量化（QLoRA），不需要独立量化步骤
- **不选原因**：BNB 量化模型在 vLLM 中性能不如 GPTQ 量化模型

#### 3. AWQ (Activation-aware Weight Quantization)
- **特点**：基于激活感知的量化，精度更高
- **GitHub**：https://github.com/mit-han-lab/llm-awq
- **适用场景**：对量化后精度要求高时
- **不选原因**：vLLM 对 AWQ 支持稍晚于 GPTQ，本项目优先选择成熟方案

#### 4. GGUF (llama.cpp)
- **特点**：CPU/GPU 混合推理，跨平台
- **GitHub**：https://github.com/ggerganov/llama.cpp
- **适用场景**：在 CPU 上部署、Mac 上部署
- **不选原因**：本项目用 GPU 部署，vLLM 是 GPU 推理的最佳选择

#### 5. SmoothQuant
- **特点**：平滑激活值分布的量化方法
- **GitHub**：https://github.com/mit-han-lab/smoothquant
- **适用场景**：超大模型量化
- **不选原因**：7B 模型不需要这么复杂的量化方法

| 框架 | 量化精度 | 推理速度 | vLLM 兼容 | 易用性 |

## 🛠️ 部署框架对比

### 本项目使用：vLLM
- **优点**：吞吐量最高、PagedAttention 创新、OpenAI 兼容 API
- **缺点**：显存占用相对较大

### 其他可选框架

#### 1. TGI (Text Generation Inference)
- **特点**：HuggingFace 官方推理服务
- **GitHub**：https://github.com/huggingface/text-generation-inference
- **适用场景**：HuggingFace 生态深度用户
- **不选原因**：吞吐量比 vLLM 低 20-30%

#### 2. SGLang
- **特点**：新兴框架，结构化生成场景性能强
- **GitHub**：https://github.com/sgl-project/sglang
- **适用场景**：复杂结构化输出（如 JSON、SQL 生成）
- **不选原因**：相对较新，社区规模小于 vLLM

#### 3. TensorRT-LLM
- **特点**：NVIDIA 官方，极致性能
- **GitHub**：https://github.com/NVIDIA/TensorRT-LLM
- **适用场景**：生产环境极致延迟要求
- **不选原因**：编译流程复杂，对初学者不友好

#### 4. Ollama
- **特点**：极简部署，一行命令运行模型
- **GitHub**：https://github.com/ollama/ollama
- **适用场景**：本地开发测试、Mac 部署
- **不选原因**：吞吐量低，不适合生产环境高并发

#### 5. MLC-LLM
- **特点**：跨平台部署（含手机、浏览器）
- **GitHub**：https://github.com/mlc-ai/mlc-llm
- **适用场景**：边缘设备部署
- **不选原因**：本项目是服务器端部署，不需要跨平台

## 📊 本项目技术选型总结

| 环节 | 本项目选择 | 替代方案 | 选择理由 |
|------|----------|---------|---------|
| 微调 | LLaMA-Factory | Axolotl / Unsloth / PEFT | 中文文档好、配置简单 |
| 量化 | AutoGPTQ | GPTQModel / AWQ / BNB | 稳定、与 vLLM 兼容性好 |
| 部署 | vLLM | TGI / SGLang / TRT-LLM | 吞吐量最高、API 兼容 |
